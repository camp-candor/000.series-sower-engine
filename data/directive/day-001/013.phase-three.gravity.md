## 1. Failure (A): `[1]` hangs the TUI

### Root Cause

`emitConsole` in `13.primordial.unit/buz/primordial.buzz.ts` (and the identical
helper in `17.tick.unit/buz/tick.buzz.ts`) preferred `ste.hunt`. `ste` is the
`300.engine` bus (`packages/300.engine/hunt.ts`). That bus has no console
reducer, so nothing ever calls `slv` for `[Console action] Update Console`.
The hunt promise never resolved, `initPrimordial` / `seedPrimordialAction`
never returned, and the `98.menu.unit` loop froze.

### Fix

Both helpers now route **only** through `(global|globalThis).LIBRARY.hunt`,
matching the certified `02.database.unit` pattern. The `ste` argument is kept
(as `_ste`) so the signature stays the same.

### Verification

* Live probe through the real engine bus (`hunt.ts`) with a stubbed
  `global.LIBRARY`: `INIT_DATABASE -> ENSURE_SCHEMA_DATABASE -> INIT_PRIMORDIAL
  -> SEED_PRIMORDIAL` all resolved (3 s timeout per step). `cns00` received:

```text

>> [PRIMORDIAL:SEEDED] [OK] Genesis (S_0) minted! H_root: 269b62e5... | EventHash: 1686cb4b...
```

* New regression test in `primordial.test.ts`: if `ste.hunt` stalls forever,

## 2. Failure (B): H_root / EventHash differ from `7f8a9c...` / `cb42a1...`

### Ruling

The `7f8a9c1e...` / `cb42a1...` strings in `011` (User Story and Interaction
sections) and `012` (Level 6) are **illustrative placeholders**. You cannot get
them from the spec's own `DEFAULT_PRIMORDIAL_BASELINE`. A correct SHA-256 only
lands on a chosen prefix if you grind a nonce into the payload, and that would
corrupt the Byte-0 baseline contract. **Decision: keep the true hashes.**

### Canonical Genesis Values (Byte-0 lock)

| Quantity | Inputs | Value |
| --- | --- | --- |
| `H_root` | RFC 8785 canonical `DEFAULT_PRIMORDIAL_BASELINE` -> SHA-256 | `269b62e561208e759c32b73b697159774373cabe954940cafe5df9c931a8eabd` |
| Sequence #1 `EventHash` | `computeChainedEventHash(GENESIS_HASH_64, evt_genesis_000)`, `seededAtMs = 1700000000000` | `1686cb4b477f1074b4f6ff8d281adf6daefc83f32f09968cb553224ec1422c70` |

These values are pinned as a golden-hash regression in
`packages/300.engine/13.primordial.unit/primordial.test.ts`. If the baseline or
the envelope sealing changes, the test fails.
