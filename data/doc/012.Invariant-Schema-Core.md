### Mathematical Invariants & Deterministic Serialization Constraints

To guarantee bit-identical state simulation across heterogeneous platforms—including local developer workstations, ARM64 build servers, and edge WebAssembly isolates—the schema core enforces four mathematical invariants at the byte boundary:

#### 1. Integer Basis-Point Quantization

Floating-point arithmetic introduces microscopic rounding divergences across instruction set architectures (IEEE-754 variances across AMD64, ARM, and V8 runtimes). Canonical schemas strictly prohibit floating-point scalars. All severities, acoustic dampening values, psychological stress metrics, physical fatigue thresholds, and probabilities are quantized into integer basis points (bp) bounded between $0$ and $10{,}000$:

$$
10{,}000\text{ bp} \equiv 1.0 \quad (100\%), \quad 1\text{ bp} \equiv 0.0001 \quad (0.01\%) \text{}
$$

Every physical ratio, condition severity, and probability threshold must map precisely within this closed integer interval.

#### 2. Deterministic Banker's Rounding (Round-Half-Even)

When scalar scaling operations are applied to basis points, calculations must never utilize floating-point division. The engine enforces an exact integer quotient and modulo evaluation:

$$
\text{For inputs } A, B \in [0, 10{,}000]: \quad P = A \times B, \quad Q = \lfloor P / 10{,}000 \rfloor, \quad R = P \pmod{10{,}000} \text{}
$$

The rounded result resolves via round-half-even:

$$
\text{Scale}(A, B) = \begin{cases} Q & \text{if } R < 5{,}000 \\ Q + 1 & \text{if } R > 5{,}000 \\ Q & \text{if } R = 5{,}000 \text{ and } Q \equiv 0 \pmod 2 \quad (\text{even}) \\ Q + 1 & \text{if } R = 5{,}000 \text{ and } Q \equiv 1 \pmod 2 \quad (\text{odd}) \end{cases} \text{[cite: 1, 7]}
$$

All chained scaling calculations must be strictly left-associative, evaluating sequentially from left to right as $\text{Scale}(\text{Scale}(A, B), C)$ to prevent associative rounding discrepancies[cite: 1, 7].

#### 3. Acoustic centi-Decibel (cdB) Standard

Acoustic energy, ambient room noise, and barrier transmission losses are measured exclusively in integer centi-decibels ($100\text{ cdB} = 1\text{ dB}$). This eliminates precision degradation when propagating acoustic waveforms through multi-edge spatial meshes. When sound travels from a source cell through intermediate portals and barriers to a listener, the final arrival intensity is calculated via discrete integer subtraction:

$$
I_{\text{arrival}} = I_{\text{source}} - \sum_{\text{barrier } k} D_{\text{edge}, k} \text{[cite: 1, 54]}
$$

#### 4. Absolute Temporal & Entropy Sealing

The canonical compile pass must produce identical byte streams regardless of the executing machine, environment variables, or build time. The compiler strictly forbids dynamic runtime wall clocks, system timestamps, and ambient pseudorandom seeds. All object keys are recursively sorted by UTF-8 code point values in compliance with RFC 8785 canonical JSON formatting, and all string properties undergo Unicode Normalization Form C (NFC). Markdown source dossiers are validated by a frontmatter sentinel requiring byte-zero compliance, rejecting leading carriage returns, whitespace, or invisible UTF-8 Byte Order Marks (BOM).

### The Somatic Hand-Capacity SAT Solver

To prevent impossible physical actions—such as a character with a severed arm wielding a two-handed weapon while holding an oil lantern—the engine evaluates an in-memory Boolean Satisfiability (SAT) solver at $T_0 = \$0.00$ before approving any action payload.

```
│ 2. Aggregate Penalties: TotalPenalties = ∑ condition.impairment_arms  │
│ 3. Compute Net Capacity: NetArmsAvailable = max(0, Gross - Penalties)  │
│ 4. Sum Equipment Demands: RequiredHands = ∑ item.occupies_hands        │
│ 5. Evaluate Invariant: RequiredHands ≤ NetArmsAvailable               │

│ [FAIL] Emit [SOMATIC_OVERLOAD] Violation ──► Instant Compilation Abort │

```

The SAT solver executes across three distinct mathematical steps:

1. **Net Functional Limb Resolution:** The solver extracts the baseline arm count from the somatic vector and iterates through all active somatic conditions. It aggregates impairment penalties (where an amputated arm deducts one unit, or a bilateral crush injury deducts two units) to calculate net usable limbs:
  $$
  \text{NetArmsAvailable} = \max\left(0, \text{GrossArms} - \sum_{\text{conditions}} \text{ImpairmentPenalty}\right) \text{}
  $$
2. **Possession Occupancy Summation:** The solver inspects the logistical vector's primary and secondary held slots. It resolves the referenced items from the canonical possession registry, extracting each item's integer hand occupancy rating. Light tools or scrap require zero hands when stowed, standard tools require one hand, and load-bearing weapons or heavy mining equipment require two hands. Unregistered foreign items default to a conservative penalty of one hand:
  $$
  \text{RequiredHands} = \sum_{i \in \{\text{HeldPrimary}, \text{HeldSecondary}\}} \text{OccupiesHands}(i) \text{[cite: 1, 51]}
  $$
3. **Invariant Verification:** The solver evaluates the fundamental inequality:
  $$
  \text{RequiredHands} \le \text{NetArmsAvailable} \text{[cite: 1, 51]}
  $$
  If the required hand slots exceed net available limbs, the solver trips an immediate `SOMATIC_OVERLOAD` exception[cite: 1, 51]. The mutation is rejected, no ledger commit is executed, and zero GPU or LLM inference tokens are burned. Validated payloads pass through a recursive deep-freeze gate that seals all nested objects, arrays, and properties in memory, causing any subsequent runtime script that attempts to mutate physical reality to throw an immediate, unhandled TypeError.
