## 1. What This Software Is

`series-sower-engine` is the **simulation kernel and "legislative authority"**
of a deterministic, AI-assisted episodic-series pipeline (the repo
`package.json` description: "Simulation Engine and Legislative Authority").

Its job: be the single deterministic authority over *physical and social
reality* of a fictional world, so that an untrusted LLM writing prose can never
produce impossible or contradictory fiction. The design law (from
`data/overview/Overview_ NPM-Agent.00.md`):

> The untrusted agent proposes intents; deterministic code disposes state.

Concretely `packages/300.engine` provides 25 numbered "units" (BEE reactive
units) that track:

- **State**: four isolated vectors - Somatic (body, wounds), Logistical
  (inventory, hands), Epistemic (what each character believes), Relational
  (debts "strings", grievances, paranoia clocks).
- **Time**: ticks. Reduction budget must stay `<= 2.0 ms` per tick.
- **Arithmetic**: integer basis points (`0..10000`), 64-bit `BigInt`, Banker's
  rounding (Round-Half-Even). Floats are rejected.
- **History**: an append-only, SHA-256 hash-chained event log with v1->v3
  schema upcasting and deterministic replay.
- **Conflict**: Stage 3 grievance lottery and Stage 4 dual-set 2d6 resolution.
- **Dialogue contracts**: dual-field dialogue AST with a curtness budget.
- **Canon compile**: a 3-pass compiler (`21.compile.unit`) with a Merkle root
  and a "Parallax Dinner" pre-flight gate.

Everything runs locally, offline, at **`T_0 = $0.00`** (zero cloud cost, zero
GPU, zero tokens). The terminal cockpit (Blessed TUI, 12x12 grid) is the window
into all of it. The cockpit host is `apps/995.library` (immutable harness).

The repo is also guarded by an unusually strict **verification gauntlet**
(Section 11) that mechanically prevents architectural drift. A large part of
"using" this repo is running that gauntlet and keeping it green.

## 3. Requirements, Install, Setup

**Prerequisites**

| Item | Requirement | Source |
|---|---|---|
| Node.js | `>= 20.0.0` for this repo (`goblin-lore` needs `>= 22.0.0`) | `package.json` `engines` |
| npm | `>= 10.0.0` | `package.json` `engines` |
| Git | any recent | hooks, gauntlet stages |
| Terminal | ANSI color support (Windows Terminal, PowerShell, iTerm2, Linux TTY) | Blessed TUI |
| OS | Windows and POSIX both supported; scripts are Node-based | AGENTS.md section 1.7 |

Because the cockpit repos are used side by side, install **Node 22** and you
satisfy all three.

**Step-by-step install (first time)**

1. Open a terminal in `D:\trellis\000.series-sower-engine`.
2. Install dependencies for all workspaces (`packages/*`, `apps/*`):

   ```bash
   npm ci
   ```

   Use `npm install` only if `package-lock.json` must change. Do **not** use
   Yarn, PNPM, Bun, Nx, Lerna, or Turborepo (forbidden by AGENTS.md).
3. Confirm the environment file exists. A `.env` is present at the repo root
   (loaded by `run.ts` via `dotenv/config`). There is no `.env.example` in this
   repo. The engine units themselves need **no** secrets: the engine is a pure
   isolate. Secrets only matter for `apps/worker` / `100.agent` (Cloudflare
   Worker, GitHub tools), which you do not need for engine work.
4. Run the fast perimeter check to prove the checkout is healthy:

   ```bash
   npm run check:preflight
   ```

   Expected: all four sub-checks exit `0` (runner boundary, harness boundary,
   artifact leak scan, 7-bit ASCII scan).
5. Optional but recommended, prove the whole repo is green:

   ```bash
   npm run gauntlet
   ```

   This takes a while (type build, prettier, eslint, dependency-cruiser, vitest,
   anti-gaming). All stages must exit `0`.

If `check:preflight` fails with a dirty immutable boundary, see
Section 13 and Section 18.

## 4. Launching the Software

### 4.1 Interactive cockpit (TUI)

There are two launch commands defined in `package.json`:

| Command | Resolves to | Where you land |
|---|---|---|
| `npm run dev` | `npm run dev --workspace=@camp_candor/995.library` | The ROOT menu (no `-t` target) |
| `npm run tui` | `npx tsx apps/995.library/run.ts -t pivot` | Straight into the **PIVOT** package menu (`000.pivot`), not the engine |

**To open the Simulation Engine directly** (this is the one you want):

```bash
npx tsx apps/995.library/run.ts -t engine
```

How `-t <idx>` is matched (`run.ts`, `init()`): the value is compared
case-insensitively against each mounted package's `name`, `globalKey`,
`menuTitle`, the suffix after the first dot, and so on. For `300.engine` the
accepted values are therefore: `300.engine`, `engine`, `ENGINE`,
`SIMULATION ENGINE`. Two special targets:

| `-t` value | Effect |
|---|---|
| `arithmetic` or `arithmetic-menu` | Opens `300.engine` directly in the **Arithmetic** cockpit (`OPEN_ARITHMETIC_MENU`) |
| `library` | Skips package auto-dispatch; opens the root menu |

> [!NOTE]
> `AGENTS.md` says: do not pass extra CLI flags to `npm run dev` during the
> Level 4 TUI audit. The `-t` flag above is for normal use via `npx tsx ...`.

### 4.2 What happens when you press launch (so you can debug it)

1. `run.ts` parses CLI flags. If any **headless flag** is present (Section 12)
   it runs that audit, prints a receipt, and exits with code `0` or `1`
   *without* starting the TUI.
2. `resolveRepoRoot()` makes the process `chdir` to the repo root and prints
   `>> [CWD] Terminal Orchestrator rooted at: ...`.
3. It scans `packages/` for directories containing `tsconfig.json`, and
   prints `>> [BUILD] Compiling N TypeScript References (tsc -b)...` with a
   heartbeat every 3 seconds. A compile error here prints formatted feedback and
   exits `1`.
4. `init()` boots the immutable Blessed harness
   (`apps/995.library/dist/995.library`), assigns it to `global.LIBRARY`, prints
   a banner `<repo-name> v<version>`, and logs `>> [OK] Master Bus Initialized`.
5. For every package it injects its `hunt` instance as `global.<globalKey>` and
   `global.PIVOTS[...]`, then registers a root menu route. For `300.engine`
   this is global key `ENGINE`, title `SIMULATION ENGINE`, description
   "Inspect simulation fences, boundary gates, and budget profilers.". It also
   registers a second route, `ARITHMETIC KERNEL AUDIT`
   ("Open Arithmetic Kernel Cockpit (Bounds, Banker Rounding, Gauntlet).").
6. It prints `>> [READY] Terminal Cockpit active` and
   `:: [KEYS] UP/DOWN or J/K: Navigate | ENTER: Select`.

### 4.3 Headless (no UI)

Every headless flag is documented in Section 12. The simplest example:

```bash
npx tsx apps/995.library/run.ts --gauntlet
```

## 5. Screen Anatomy and Keyboard

**Layout (immutable 12x12 dual-pane topology; AGENTS.md section 1.6):**

```text
+-------------------+-----------------------------------------------+
|  LEFT PANE        |  RIGHT PANE  (cns00)                          |
|  Columns 0-4      |  Columns 4-12                                 |
|  rows 4-12        |  rows 0-12                                    |
|                   |                                               |
|  Interactive      |  - Boot banner                                |
|  vertical list    |  - Focus tooltips (description of the         |
|  of choices       |    highlighted choice)                        |
|                   |  - Live telemetry, audit receipts, redlines   |
+-------------------+-----------------------------------------------+
```

- You make choices **only** in the left pane. All output appears in the right
  pane (`cns00`).
- Highlighting a choice prints its description into `cns00` **before** you press
  ENTER. Use this as a free preview.
- After you press ENTER on an action, the receipt prints in `cns00` and the
  menu re-renders automatically (the arithmetic menu re-arms ~333 ms later).

**Keys (as printed by the cockpit and shared by the harness):**

| Key | Effect |
|---|---|
| `UP` / `DOWN` or `K` / `J` | Move highlight |
| `ENTER` | Execute highlighted choice |
| `q`, `Ctrl+C`, or `ESC` twice quickly | Quit the whole app. **[UNVERIFIED in this repo]**: confirmed in the `goblin-lore` manual for the same immutable harness; the harness source lives in `apps/995.library/995.library` and is read-only. |

To leave a submenu without quitting, choose `ROOT MENU` (or `[ROOT MENU]`).

## 13. Repo Laws You Must Not Break

Condensed from `AGENTS.md` (authoritative). Violating these fails the gauntlet:

1. **Plain npm monorepo**; `"private": true`; root `package.json` has **no**
   runtime `dependencies`.
2. **`packages/300.engine` is a pure isolate.** No `src/` directory. All logic
   lives in `<NN>.<name>.unit/{act,buz,fce,val}`. No `node:fs`, `child_process`,
   `net`, `http`, `https`, `tls`, `better-sqlite3` in non-test engine files
   (sole exception: `00.engine.unit/buz/gauntlet.buzz.ts`). No `remotion`,
   `react`, `@cloudflare/*`, `puppeteer`, `playwright`, `canvas`,
   `fluent-ffmpeg`, `three`, `pixi.js`.
3. **Determinism:** `BigInt` and basis-point integers for simulation state.
   Time budgets via `process.hrtime.bigint()`. Tick reduction `<= 2.0 ms`.
4. **TypeScript:** strict ESM, `NodeNext`, relative imports end in `.js`. No
   emitted `.js`/`.d.ts`/`.js.map` beside source; builds go to `dist/`.
5. **7-bit ASCII only** in manifests, `scripts/**`, `300.engine/**`, `run.ts`.
   Use `>>`, `::`, `---`, `[OK]`, `[PASS]`, `[FAIL]`, `[BREACH]`.
6. **No `console.log/warn/error` in `packages/300.engine/**`.** Route telemetry
   through `global.LIBRARY.hunt('[Console action] Update Console', { idx:
   'cns00', ... })`. Every menu buzzer needs a headless fallback when
   `global.LIBRARY` is undefined.
7. **The dual-pane layout is immutable** (left 4 columns = 6 choices bound with
   `net`, right 8 columns = `cns00` plus `WRITE_CONSOLE`).
8. **Immutable perimeter:**

   | Path | Rule |
   |---|---|
   | `apps/995.library/995.library/**` | Never edit |
   | `apps/995.library/run.ts` | Only permitted change point there (route mounting) |
   | `apps/worker/wrangler.jsonc` | Never edit |
   | `packages/300.engine/00.engine.unit/test/**`, `17.tick.unit/tick.spec.ts`, `packages/300.engine/test/**`, `.dependency-cruiser.cjs`, `vitest.workspace.ts` | Held-out overlay: overwritten from `HEAD` by `check:anti-gaming` |
   | `data/overview/**`, `data/building/**`, `data/directive/**` | Append-only history |

9. **3-strike rule:** if a failure persists after 3 consecutive fixes, stop,

10. **Git:** no commits to `master`; branch names match
    `^[a-zA-Z0-9]+([/-][a-zA-Z0-9]+)*$`; conventional commits (`feat:`, `fix:`,
    `chore:`, `refactor:`, `test:`, `docs:`, `ci:`); never use `--no-verify`;

### 14.4 Programmatic dispatch (custom inputs)

Everything in the menu is an action on the engine's `hunt` bus. After the
cockpit boots, `global.ENGINE` (and `global.PIVOTS['300.engine']`) expose

// Stage 3 encounter with your own cast (ActGrv = 06.grievance.unit/grievance.action)
await ENGINE.hunt(ActGrv.SELECT_STAGE3_ENCOUNTER, {

            currentTensionBps: 5000,
            tick: 1,
            timestamp_ms: 1700000000000,
        },
    },
})

> constants are defined in each unit's `*.action.ts` (for example
> `packages/300.engine/08.ledger.unit/ledger.action.ts`). **Import the constant
> rather than typing the string**, as the menu code does

> shape is `{ idx, src, val, dat, slv }` and the payload keys inside `dat` are
> exactly the ones shown in the Section 7.1 table.

### 15.3 How lore feeds the engine (explicit hand-off, step by step)

Today this is a **manual, file-based contract**; there is no automatic link
(Section 2.3).

**What lore produces (its output artifacts):**

| Artifact | Path (in `000.goblin-lore`) | Meaning |
|---|---|---|
| Canon sources | `lore/series/<slug>/*.md` (also `series/<slug>/{characters,locations,possessions,grievances,world}/*.md`) | Authoritative Markdown dossiers |
| Sealed snapshot | `compiled/<slug>/bible-state.json` | Deterministic compile output (RFC 8785 JCS) |
| Archive snapshots | `compiled/<slug>/bible-state_<ISO-timestamp>.json` | History |
| `H_root` | printed as `[SEAL:MERKLE_ROOT]` | SHA-256 Merkle fingerprint of the canon |
| Errata ledger | `series/<slug>/world/errata.json` | Hash-chained revisions of already-sealed facts |

Series currently present on disk: `000.sample-hearth`, `wiregrass-basin`,
`under-the-floorboards` (note the engine menu's fixed payloads use
`under-the-floorboards`, and its compile fixture uses `wiregrass-basin`).

**Hand-off procedure:**

1. In `000.goblin-lore`: author or edit dossiers, then in the cockpit run
   `[C] COMPILE CANON & GATE 0 GAUNTLET` -> `[1]` (fix any `[FAIL]`), then
   `[5] GATE 0` and confirm zero drift.
2. Record `H_root` from the receipt and commit
   `git add series lore compiled; git commit -m "feat: seal <slug> canon at H_root <first-8>"`.
3. Make the sealed canon visible to the engine. Choose one:
   - **A (recommended, no code changes):** treat `compiled/<slug>/bible-state.json`
     as the contract file. Keep it in the lore repo, and when you need it in the
     engine, copy it into a fixture location in this repo (for example a new
     `*.fixture.ts` or JSON beside `21.compile.unit/buz/`) via a normal feature
     branch. Because `300.engine` forbids `node:fs`, **the engine cannot read
     files at runtime by itself**; the data must be passed in as an object by
     the caller (the harness/`run.ts`, a test, or a script outside
     `packages/300.engine`).
   - **B (developer):** have `apps/995.library/run.ts` (the only mutable file in
     that app) read the lore file and pass the parsed corpus into
     `21.compile.unit` as the `corpus` field of `run-compile` (the same field the
     fixture fills today: `dat: { seriesSlug, corpus }`).
4. In this repo, run `COMPILE & PREFLIGHT PARALLAX DINNER`. Compare the
   engine's `[MERKLE:ROOT]` against lore's `H_root` for the same corpus:
   identical canonical JSON must give identical roots. A mismatch means the
   canon and the engine disagree - fix the corpus or the kernel, never the
   test.
5. Boot the engine on that series (`[01] BOOT ENGINE`, which currently uses
   `seriesSlug: 'under-the-floorboards'` in the fixed payload; for another slug,
   dispatch `BOOT_ENGINE` programmatically with `bootParams.seriesSlug`).
6. Run the simulation menu (Section 14.3). Characters from lore (for example
   `char_bog`, `char_wart`) appear as the engine cast.

**Rules lore enforces that the engine relies on:** every dossier starts with
`---\n` (Byte-0), 7-bit ASCII, integer basis points, hands `<=` effective arms,
exactly 2 principals per grievance, acyclic escalation chains, reciprocal
portals. If lore compiles clean, the engine's compile Pass 1 and Pass 2 should
also pass.

### 15.4 Errata round trip

When a sealed fact changes (for example the width of a culvert):

1. Lore: edit the dossier, recompile (`[C] [1]`), then `[X] RECORD CANONICAL
   ERRATA ENTRY` to append a hash-chained errata record.
2. Lore: `[ 26. SCHEMA & INVARIANTS ]` -> `[ 4. CRYPTOGRAPHIC ERRATA LEDGER ]`
   to verify the chain.
3. Engine: re-compile (new `H_root`), and use `Verify Event Hash Chain` to show
   that historical engine events were not rewritten (the engine log is
   append-only; errata, not edits, record the change).

### 16.3 How spatial feeds the engine

The overview defines the contract: spatial emits **plain-data receipts**
(reachable sets, ray intersections, centi-decibel (cdB) acoustic arrival levels,
`PerceptCandidate` records with modality, relative bearing, and signal-to-noise
margin). The engine then applies:

1. **Somatic gate:** drop the percept if the observer's `SomaticVector` blocks it
   (ear trauma, noise below the ambient floor, outside the facing cone, blocked
   by occlusion).
2. **Epistemic gate:** convert surviving percepts into `BeliefRecord`s
   (confidence in basis points, `hop_count`, source type).
3. **Atomic event log:** append the mutation `S_n -> S_n+1` to the SQLite
   hash-chained log.

The engine already carries its own **small** spatial implementation
(`10.location.unit`, `11.movement.unit`) so it can be tested in isolation. The
menu options `Audit Spatial Topology & Portal Mesh` and `Audit Axial Locomotion &
Movement Gating` exercise that internal version; goblin-spatial is the
full-scale, independently versioned oracle with the same axial integer math.

**Hand-off procedure (manual, like lore):**

1. In goblin-spatial: load the topology (`[TOP01]`) for the same location
   dossiers that lore sealed (portal edges and `damping_cdb` in lore's location
   frontmatter correspond to spatial edges and cdB attenuation).
2. Evaluate the query you care about (for example `[LOS01]` raycast) and capture
   the receipt data (plain JSON; no identities).
3. Pass the receipt into the engine as input to the somatic/epistemic stages
   (`[15] AUDIT EPISTEMIC HORIZONS & SUBTEXT ATTENUATION` shows how an observer's
   knowledge is scrubbed and attenuated; `[14]` folds the resulting events).
4. Use `Audit Axial Locomotion & Movement Gating` to confirm a character's
   locomotion tier permits the traversal spatial says is geometrically possible
   (for example a `BIPEDAL_HUNCHED` character cannot `SPRINT`).

Because the repos do not import each other, **the numbers must agree by
construction**: both use integer coordinates, basis points, and centi-decibels
(never floats). A disagreement is always a bug in one of the repos.

## 17. Cross-Repo Master Workflow

The most effective way to reach the goal of this ecosystem ("a sealed,
simulation-verified series with zero impossible fiction at `$0.00` compute"):

| Phase | Repo | Action | Success signal |
|---|---|---|---|
| 0 | all | `node -v` is 22+; `npm ci` in all three repos | no errors |
| 1 | engine | `npm run check:preflight` | all `0` |
| 2 | lore | Genesis (`[G]`) or hand-write `series/<slug>/`; write conditions, characters, locations, grievances | files start with `---` |
| 3 | lore | Audits: `[ 26. SCHEMA & INVARIANTS ]` options 1-8, `[H] STATIC CORPUS HEALTH TELEMETRY` | `[OK]` receipts, health card `[HEALTH:OK]` |
| 4 | lore | `[C]` -> `[1]` full gauntlet -> `[5]` Gate 0 | `[STATUS:FINAL] [SEALED]`, `H_root` printed |
| 5 | lore | commit canon with `H_root` in message | clean `git status` |
| 6 | spatial | Load topology for those locations; validate lattice, raycast, acoustic decay | `Manifest Loaded`, expected raycasts |
| 7 | engine | Bring canon in (Section 15.3), `COMPILE & PREFLIGHT PARALLAX DINNER` | `[SEALED]`, `[PREFLIGHT:PASS] ... Certified`, root matches lore |
| 8 | engine | `[01] BOOT`, run beat workflow (Section 14.3) | receipts `[OK]`, hash chain verifies |
| 9 | engine | `npm run gauntlet` | exit `0` across all stages |
| 10 | downstream | Hand the dialogue AST (`[16]`) to the conductor | frozen `dialogue_ast.json` (conductor repo is out of scope) |

Cadence recommendation: author in lore in short loops (steps 2-4), only
seal/commit (step 5) when Gate 0 is clean, and never touch the engine's
held-out tests to make a failure disappear; fix the cause.

## 18. Troubleshooting and Known Quirks

| Symptom | Cause | Fix |
|---|---|---|
| `check:preflight` fails on harness or `wrangler.jsonc` | Immutable files modified | `git restore apps/995.library/995.library/ apps/worker/wrangler.jsonc` |
| Leaked `.js`/`.d.ts` in `packages/300.engine` | A stray `tsc` emit | `npm run clean:js`, then `npm run check:preflight` |
| `npm run clean`, `clean:js` fail on Windows | They use `find`, which is not in PowerShell/cmd | Use Git Bash/WSL, or delete `dist/` and the artifacts manually. This also conflicts with AGENTS.md section 1.7 (cross-platform scripts); consider converting them to Node scripts. |
| `npm run tui` opens PIVOT, not the engine | The script hardcodes `-t pivot` | Use `npx tsx apps/995.library/run.ts -t engine` |
| `>> [BUILD]` step fails with TypeScript errors | `tsc -b` runs before the UI | Fix the type error; re-run |
| An engine menu option seems to hang | The authors note routed `ste.hunt` console telemetry "never settles" in the TUI | Use the headless flag, or `[03]`-style direct call |
| `[WARN] Skipping pivot [x]` on boot | A package failed to load | Read the message; fix or ignore if you do not use that package |
| `AUDIT ANTI-GAMING OVERLAY` wiped my edits | It restores protected paths from `HEAD` by design | Commit or stash first; never edit held-out tests |
| `npm run gauntlet` fails prettier | Formatting | `npm run fix`, rerun |
| Compile preflight reports non-ASCII | Pasted smart quotes | `npm run sanitize:fountain` |
| Lore compile uses `000.sample-hearth` when you expected your series | Lore falls back to the sample series if `lore/series/<slug>` is missing | Create or fix the directory (see lore manual drift note D4) |
| `.env` missing keys | Only the Worker/agent needs secrets | Ignore for engine work |

Known limitations worth knowing:

- The engine menu dispatches use **fixed demo payloads**; there are no input
  prompts (except in the lore deck's motor lab).
- The `[N]` numbered legacy labels overlap in number with the 2-digit
  `[NN]` primary labels (for example `[8]` appears for both "Upcaster" and
  "Spatial Topology"). Labels are unique as strings, so routing works; just
  pay attention to the full text.
- The anti-gaming "5/5 Golden Traps Active" line is static text; the real
  verdict is the `[PASS: BASELINE LOCKED]` / `[FAIL: DEFECT DETECTED]` line.
- Cross-repo integration is manual today (Section 2.3).
