The **Deterministic Arithmetic Rounding Kernel** provides the foundational mathematical bed of the simulation engine, operating as an isolated, zero-I/O legislative component on Rig 1 CPU memory heaps prior to any distributed edge isolate deployment. Standardizing all dynamic simulation calculations—such as somatic strain, acoustic decibel attenuation, psychological refusal thresholds, and spatial transit velocity—on float-free arithmetic eliminates cross-platform divergence across AMD64 workstation processors, Apple Silicon/Graviton ARM64 instruction pipelines, and edge WebAssembly V8 isolates. Under standard IEEE-754 floating-point operations, differences in compiler vectorization instructions, extended precision registers, and Fused Multiply-Add (FMA) implementations yield microscopic rounding discrepancies at the sixteenth decimal place. In continuous iterative simulation loops, these sub-bit variances compound across state trees, altering relational branches, corrupting cryptographic state receipts, and producing divergent Merkle root digests ($H_{\text{root}}$).

### Foundational Architectural Governance & Directory Fencing

The arithmetic kernel enforces rigid architectural boundaries to maintain deterministic isolation across the engine workspace:

- **Directory Fence Law:** The module is strictly quarantined within numeric unit containers under the packages directory (specifically located inside the arithmetic unit container). The creation or use of generic source directory structures (`src/`) is categorically banned to prevent unordered, circular compilation dependencies. All models, pure mathematical actions, action bit command descriptors, and boundary fuzzers are segregated into modular sub-units.
- **Absolute Floating-Point Prohibition:** Continuous single-precision and double-precision floating-point scalars (`f32`, `f64`) are banned from all authoritative state calculation pathways. Incoming numbers are validated at the runtime perimeter to reject non-integers, sub-normal numbers, infinities, and NaN payloads.
- **Read-Only Purity and Memory Isolation:** The kernel maintains zero active host dependencies: it executes without querying wall clocks (`Date.now()`), without reading host environment variables, without invoking host-dependent pseudo-random number generators, and without initiating network or disk I/O.
- **Deep-Freeze Mutation Defense:** Every calculation output emitted by the kernel is recursively deep-frozen prior to returning payloads to calling units (such as the paranoia unit, transit spline unit, and duel math unit), ensuring that downstream runtime scripts cannot alter shared memory references.

### Nominal Quantization: The Basis-Point Integer Standard

To represent fractional multipliers, probabilities, and physical constants without continuous decimals, the engine standardizes all continuous dimensions into discrete **Integer Basis Points** ($0$ to $10{,}000$ bp):

- **Canonical Quantization Unit:** The basis-point integer standard maps $10{,}000\text{ bp} \equiv 1.0000$ ($100.00\%$) and $1\text{ bp} \equiv 0.0001$ ($0.01\%$). Physical damage scaling, biological trauma, spatial occlusion factors, and lighting dampening are forced into this closed integer domain.
- **Nominal Type Branding:** At the type-system boundary, basis points are tagged as nominal branded types rather than raw untyped integers. Runtime type assertion predicates validate that operands are finite integers and fall strictly within the inclusive range $[0, 10{,}000]$, throwing explicit range or type faults upon the detection of negative values or fractional floating numbers.
- **Extended Precision Typings:** For multi-hop graph traversals, regional transit integrations, and cumulative campaign timelines, the kernel provides sixty-four-bit BigInt nominal basis-point typings to eliminate integer overflow hazards.

### The Four-Case Round-Half-Even (Banker's Rounding) Specification

Standard integer truncation introduces a systematic downward bias that causes repeated scalar multiplications to collapse numbers prematurely toward zero. For instance, evaluating fractional products such as $(1 \times 1) / 10{,}000$ under downward truncation immediately drops to zero, causing small accumulated values or subtle environmental debuffs to vanish. Conversely, naive round-half-up formulations (such as adding half the denominator prior to division) introduce an upward statistical drift over long-running campaign iterations.

To achieve zero statistical bias, scalar scaling evaluates through exact integer **Round-Half-Even (Banker's Rounding)**, breaking exact fractional ties toward the nearest even integer quotient.

#### Mathematical Formulation

Given two non-negative integer basis-point scalars $A$ and $B$, their scaled product $\text{Scale}(A, B)$ evaluates according to the following discrete remainder arbitration:

$$
\text{Let } P = A \times B \text{}
$$

$$
\text{Let } Q = \lfloor P / 10{,}000 \rfloor, \quad R = P \pmod{10{,}000} \text{}
$$

$$
\text{Scale}(A, B) = \begin{cases} Q & \text{if } R < 5{,}000 \\  Q + 1 & \text{if } R > 5{,}000 \\  Q & \text{if } R = 5{,}000 \text{ and } Q \equiv 0 \pmod 2 \quad (\text{even quotient}) \\  Q + 1 & \text{if } R = 5{,}000 \text{ and } Q \equiv 1 \pmod 2 \quad (\text{odd quotient}) \end{cases} \text{}
$$

#### Branch Analysis

1. **Strict Downward Branch ($R < 5{,}000$):** When the remainder falls strictly below the midpoint threshold of $5{,}000$ basis points, the fractional residue is discarded, maintaining the integer quotient $Q$.
2. **Strict Upward Branch ($R > 5{,}000$):** When the remainder exceeds $5{,}000$ basis points, the product is closer to the next whole unit, incrementing the quotient to $Q + 1$.
3. **Even Tie Branch ($R = 5{,}000 \text{ and } Q \text{ is even}$):** When an exact half-tie occurs and the least significant bit of the quotient is zero, the quotient remains unchanged. For example, a raw quotient of $2$ with a remainder of $5{,}000$ evaluates to $2$.
4. **Odd Tie Branch ($R = 5{,}000 \text{ and } Q \text{ is odd}$):** When an exact half-tie occurs and the least significant bit of the quotient is non-zero, the quotient increments to the next even integer ($Q + 1$). For example, a raw quotient of $1$ with a remainder of $5{,}000$ rounds upward to $2$.

### Left-Associative Chaining & Intermediate Bounding

When multiple basis-point multipliers are compounded—such as applying successive acoustic barriers, environmental darkness modifiers, and physical armor dampening—the sequence of operations directly dictates the result.

- **Strict Left-Associativity:** To eliminate compiler reordering discrepancies and ensure identical results across execution engines, chained multiplications must enforce strict left-associative sequence order:
  $$
  \text{Scale}(\text{Scale}(\text{Scale}(V, M_1), M_2), M_3) \text{[cite: 1, 2]}
  $$
- **Intermediate Scaling Mandate:** Rather than accumulating large products and performing a single division at the end of the chain, the kernel scales and rounds after *every individual multiplication step*. This guarantees that intermediate products between two basis points never exceed $10{,}000 \times 10{,}000 = 10^8$, keeping values within standard $32$-bit integer and JavaScript safe integer limits ($2^{53} - 1 \approx 9.007 \times 10^{15}$).
- **Domain Distinction:** If a specific game mechanic requires guaranteed conservative bounds (such as inventory capacity or stamina expenditures that must never overestimate resource availability), the kernel provides an explicit, separately named floor-truncation routine. Round-half-even remains the universal default; directional bias is treated as an explicit domain policy rather than an accidental byproduct of division.

### Arbitrary Integer Division: General Half-Tie Resolution

Beyond basis-point scaling (where the divisor is fixed at $10{,}000$), dynamic simulation systems must divide arbitrary integer numerators $N$ by arbitrary integer denominators $D$ (such as distributing discrete items among party members or calculating hex traversal progress).

```
┌────────────────────────────────────────────────────────────────────────┐
│               ARBITRARY INTEGER DIVISION TIE ARBITRATION               │
├────────────────────────────────────────────────────────────────────────┤
│ 1. Zero Divisor Gate: Assert D ≠ 0 (Raise RangeError on 0)             │
│ 2. Divisor Sign Normalization: If D < 0, negate both N and D           │
│ 3. Integer Division: Compute q = ⌊N / D⌋ and r = ((N mod D) + D) mod D │
│ 4. Remainder Doubling Comparison:                                      │
│    • 2r < D  ──► Return q                                              │
│    • 2r > D  ──► Return q + 1                                          │
│    • 2r == D ──► Inspect parity of q:                                  │
│                  - If q is even (q mod 2 == 0): Return q               │
│                  - If q is odd  (q mod 2 ≠ 0) : Return q + 1           │
└────────────────────────────────────────────────────────────────────────┘
```

- **Zero-Divisor Defense:** Division by zero is intercepted immediately, throwing an unrecoverable `RangeError` to halt compilation or simulation ticks.
- **Divisor Sign Normalization:** To prevent negative modulo anomalies, negative denominators are normalized such that the working divisor $D$ is strictly positive ($D > 0$), inverting the numerator accordingly.
- **Remainder Doubling Comparison:** Rather than dividing the remainder by the divisor (which would introduce fractional floating-point calculations), the algorithm doubles the remainder ($2r$) and evaluates integer inequalities against $D$:
  - If $2r < D$, the fraction is less than half; return $q$.
  - If $2r > D$, the fraction is greater than half; return $q + 1$.
  - If $2r = D$, an exact half-tie exists; inspect the least significant bit of $q$, returning $q$ if even, or $q + 1$ if odd.

#### Analytical Encounter Convergence

When two actors traverse a regional edge without per-tick coordinate steps, the exact centisecond tick of intersection is solved algebraically:

$$
\text{Head-On Meeting: } t_{\text{meet}} = \text{divRoundHalfEvenBigInt}\left(\frac{D_A D_B + T_{A,\text{enter}} D_B + T_{B,\text{enter}} D_A}{D_A + D_B}\right) \text{[cite: 8, 9, 27]}
$$

$$
\text{Same-Direction Overtake: } t_{\text{overtake}} = \text{divRoundHalfEvenBigInt}\left(\frac{T_{A,\text{enter}} D_B - T_{B,\text{enter}} D_A}{D_B - D_A}\right) \text{[cite: 8, 9, 24]}
$$

- **Magnitude Exposure:** Over a simulation spanning one hundred years, the cumulative centisecond tick count reaches approximately $3.15 \times 10^{11}\text{ cs}$. In cross-multiplication operations involving spatial traversal costs, intermediate terms scale to $\approx 2.7 \times 10^{18}$, exceeding the safe integer ceiling of $9 \times 10^{15}$. Under standard numeric types, this triggers silent truncation, resulting in invalid collision coordinates without throwing a hardware exception.
- **BigInt Promotion:** The kernel automatically routes analytical corridor meetings, overtake convergence points, and high-resolution rational progress calculations through a parallel arbitrary-precision BigInt arithmetic engine. The BigInt implementation mirrors the four-case Banker's Rounding rules identically, ensuring that high-magnitude operations and standard basis-point scalings remain mathematically congruent.

### Command Dispatch & Terminal Telemetry Integration

The arithmetic kernel integrates into the host simulation loop through a command bit router, operating without direct coupling to high-level game logic:

- **Command Bit Descriptors:** The unit exposes discrete numerical command identifiers covering scalar scaling (`SCALE_SCALAR`), chained multiplication (`SCALE_CHAINED`), arbitrary integer division (`DIVIDE_ROUND_EVEN`), and boundary audit verification (`AUDIT_TIE_BREAKS`).
- **Staging Accumulator Handoff:** Calculation requests are bundled into lightweight action bits and dispatched across the engine's event bus, returning completed, cryptographically conditionable calculation receipts into the mutable staging accumulator resident in RAM.
- **Blessed Terminal Cockpit Telemetry:** Local operators monitor the health of the arithmetic foundation via the Blessed Curses terminal cockpit. The console displays real-time telemetry confirming float rejection, quotient parity stability, and boundary remainders; any detected parity fault or float leakage triggers an immediate halt, logging the exact failing quotient, remainder, and operands to the operator buffer.
