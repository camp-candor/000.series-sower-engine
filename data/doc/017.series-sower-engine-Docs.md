## 1. What This Software Is

`000.series-sower-engine` is a **deterministic simulation kernel** for generating a
fictional "series" (an episodic story about goblins in an industrial underdark). It is
describable in plain terms as:

- A **ledger and referee**. Characters (actors) hold possessions, accumulate grievances,
  suffer trauma and wounds, and resolve conflicts with opposed 2d6 dice -- all computed
  with 64-bit integer ("BigInt") basis-point arithmetic so the same seed always
  produces the same episode. Floating-point math is forbidden.
- A **locomotive**. It runs in discrete "ticks". Every tick is capped at a hard budget
  of **<= 2.0 milliseconds** of execution.
- A **free window**. The entire kernel runs offline on your local CPU at
  **T_0 = $0.00** -- zero GPU, zero LLM tokens, zero cloud spend. The simulation itself
  never calls the network.
- A **terminal cockpit**. You drive everything through a full-screen terminal UI
  (Blessed "curses" style) launched from `npm run dev`.

The official package description is "Simulation Engine and Legislative Authority":
*simulator* (`packages/300.engine`) making story physics law, *legislature*
(`packages/300.engine/00.engine.unit` CI gauntlet) enforcing it.

## 2. The Three-Repo Pipeline

This repo is **one link in a three-studio pipeline**. It cannot be used fully in
isolation; canon comes from `goblin-lore` and physics receipts come from
`goblin-spatial`.

```text
+---------------------+     +----------------------+     +---------------------------------+
|  000.goblin-lore    |     |  000.goblin-spatial  |     |  000.series-sower-engine        |
|  (canon author +    | --> |  (physical oracle:   | --> |  (THIS REPO:                    |
|   compiler)         |     |   hex grid, sight,   |     |   simulation kernel + ledger)   |
|                     |     |   sound, paths)      |     |                                 |
|  Writes Markdown    |     |  Answers "was it     |     |  Folds events into hash-chained |
|  dossiers for a     |     |   physically         |     |  state; emits deterministic     |
|  series; compiles   |     |   POSSIBLE?"         |     |  dialogue-AST contracts.        |
|  them into          |     |                      |     |                                 |
|  bible-state.json   |     |                      |     |                                 |
+---------------------+     +----------------------+     +------------------+--------------+
                                                                               |
                                                                               v
                                                            +------------------+--------------+
                                                            |  000.series-sower-conductor     |
                                                            |  (speech synthesis + video      |
                                                            |   timeline; renders the "sown"  |
                                                            |   episodes into audio/video)    |
                                                            +---------------------------------+
```

The reality chain, in one line:

```text
Topology -> Physical State -> Physical Possibility -> Event -> Percept -> Belief -> Expression
```

- **`000.goblin-lore`** = the *canon compiler*. Authors write a story world as a catalog
  of dossiers (characters, locations, possessions, grievances, world conditions,
  economy, errata). The lore kernel validates the world against ontological law
  (integer math, anatomy, portals, grievance DAG, epistemic firewalls) and compiles it
  into a sealed JSON artifact: `compiled/<series-slug>/bible-state.json`, signed with
  an RFC 8785 JSON-canonicalization (JCS) SHA-256 Merkle root (`H_root`).
- **`000.goblin-spatial`** = the *physical oracle*. A pure integer-math hex-grid engine
  answering spatial questions: can A see B (line-of-sight raycast), can A hear B
  (acoustic wavefront with centi-decibel damping per wall material), can A walk to B
  (bounded pathfinding), and where an overcrowded goblin gets displaced.
- **`000.series-sower-engine`** (this repo) = the *sovereign ledger*. Boots a sealed
  universe from the lore's `bible-state.json`, then runs the deterministic scene loop
  (tick -> grievance lottery -> staging -> 2d6 resolution -> trauma -> state fold) and
  emits hash-chained events.
- **`000.series-sower-conductor`** (downstream) = the *renderer*. Ingests the engine's
  deterministic contracts (`dialogue_ast.json`, somatic baselines, errata records) to
  produce speech synthesis and Remotion video timelines.

**Coupling style:** the three repos have **zero import-level coupling** in code. Data
flows between them as *plain JSON artifacts copied on disk* (specifically
`bible-state.json` from lore into this repo's `compiled/` folder, and `spatialProof`
receipt hashes embedded in event envelopes). The one live machine connection is the
shared terminal harness: any repo's "LIBRARY MENU -> Progress Library" can broadcast
the `apps/995.library` TUI harness into sibling repos (see Section 16.3).

## 4. Launching the Terminal Cockpit

All launches happen from the monorepo root `D:/trellis/000.series-sower-engine`.

### 4.1 Primary launch

```sh
npm run dev
```

What happens, in order:

1. `run.ts` compiles every workspace with `tsc -b` (heartbeat prints every 3 seconds,
   so a quiet terminal is normal for a few seconds).
2. The immutable Blessed harness loads as `global.LIBRARY`.
3. The root switchboard appears and every package under `packages/` is mounted as a
   route. Boot banner streams into the right-hand console pane:
   `>> [OK] Master Bus Initialized`, then `>> [READY] Terminal Cockpit active`, then
   the key hint `>> [KEYS] UP/DOWN or J/K: Navigate | ENTER: Select`.

### 4.2 Direct targeting with `-t` (skip the root menu)

```sh
npm run tui                          # straight into the PIVOT package menu
npx tsx apps/995.library/run.ts -t engine       # straight into the engine cockpit
npx tsx apps/995.library/run.ts -t arithmetic   # straight into the arithmetic kernel menu
npx tsx apps/995.library/run.ts -t agent        # agent/worker cockpit
npx tsx apps/995.library/run.ts -t cloudflare   # cloudflare account manager
npx tsx apps/995.library/run.ts -t library      # root switchboard (same as npm run dev)
```

Valid `-t` values: `library` (default), `pivot`, `agent`, `cloudflare`, `engine`
(alias `300.engine`), `arithmetic` (alias `arithmetic-menu`).

### 4.3 Headless launch (no TUI at all)

`run.ts` understands ~60 CLI flags that run one audit and print plain text to stdout
then exit. See Section 10. Example:

```sh
npx tsx apps/995.library/run.ts --audit-fence
```

There are convenience wrappers `vrt.lib.bat` (= `npm run dev`) and `vrt.cde.bat` at
the repo root for one-click launching on Windows.

## 5. Cockpit Layout and Keyboard Controls

Every menu in every repo follows the **Blessed 12x12 Dual-Pane Cockpit** law. This
layout is an invariant -- you will always see it:

```text
+----------------------------+------------------------------------------+
|  (rows 0-3 above menus:    |  CONSOLE TELEMTRY PANE  (cns00)          |
|   banners / headers)       |  columns 4-12, rows 0-12                 |
+----------------------------+------------------------------------------+
|  CHOICE PANE               |  >> [OK] Master Bus Initialized          |
|  columns 0-4, rows 4-12    |  :: [INFO] Mounted headless pivot...     |
|  1. Choice A               |  >> [KEYS] UP/DOWN or J/K: Navigate      |
|  2. Choice B               |  (focus a choice -> its description      |
|  ...                       |   streams here as a tooltip)             |
+----------------------------+------------------------------------------+
```

- **Left pane (columns 0-4):** the interactive choices. Focused item is highlighted.
- **Right pane (columns 4-12):** the `cns00` streaming telemetry console -- banners,
  receipts, progress, error messages, and per-choice focus descriptions live here.
  **All output you need to read is in the right pane.**

### 5.1 Keyboard (verified against the immutable `85.choice.unit` harness source)

| Key | Action |
| :--- | :--- |
| `UP` or `k` | Move to previous choice |
| `DOWN` or `j` | Move to next choice |
| `ENTER` | Execute the focused choice |
| `ESC` | Cancel the current menu (returns empty selection; often navigates BACK) |
| Mouse moves/clicks | Hover and click also work (`mouse: true` is enabled) |
| `q` | Quit the whole app (clean shutdown; bound in `run.ts`) |
| `Ctrl+C` (`C-c`) | Quit the whole app (bound in the choice exit bar and `run.ts`) |
| `ESC` twice (quickly) | Quit the whole app (double-escape guard, 2.5 s window) |

Notes:

- Default/headless `q` handling: the exit bindings `q` / `C-c` are attached per repo in
  `run.ts`. Any menu choice equal to `ROOT MENU` naviges up one level.
- In the ROOT menu, selecting a package route opens that package's cockpit and the
  third `ROOT MENU` items found deeper in menus bring you back.
- Choosing an unknown item in a package menu falls through to `CLOSE_TERMINAL`
  (exits the TUI) in the `000.pivot`-style generic menus, so prefer `ROOT MENU` over
  `ESC` when "backing out" in pivot/agent/cloudflare menus.
